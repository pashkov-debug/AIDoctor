# AIDoctor 6.3.2 — изолированный локальный ClamAV (не допуск файлов)

## Назначение и границы

Это **опциональный эксплуатационный** инкремент поверх 6.3.1.
До явного запуска дополнительного Compose-файла ClamAV не скачивается
и не стартует. Старые API, модель хранения, права, Alembic, SHA-256,
Context Builder и PostgreSQL неизменны.

- **Источник истины** о карантине — PostgreSQL, но для парсеров
  `require_processing_clearance` по-прежнему **всегда запрещает** обработку.
- Оригиналы медицинских файлов остаются в закрытом каталоге приложения.
  Он **не подключён** к контейнеру ClamAV. Используется только `INSTREAM`,
  который передаёт байты текущего снимка по локальному TCP.
- Свежесть базы оценивается по **заявленной** строке VERSION, а срабатывание
  проверяется на *безвредной тестовой сигнатуре EICAR* (создаётся только в RAM).
  Успешный smoke-test **не удостоверяет подлинность clamd**: TCP не защищён.
- Никаких OCR, LLM, CDR, парсеров, внешней передачи медицинских данных,
  автоматического сканирования или снятия карантина.

## Что именно запускается

`compose.av.yaml` — отдельный, подключаемый только вручную Docker Compose
override с ClamAV. Он не меняет `compose.yaml` PostgreSQL.
Официальный образ ClamAV версии `1.5.4` требует заметных ресурсов и загрузки
сигнатур через FreshClam (внешняя сеть используется **самим ClamAV только для
обновления сигнатур**). Используется:
- контейнерный пользователь `clamav` и `/init-unprivileged`;
- `cap_drop: ALL`, `no-new-privileges`, максимум 128 процессов, 2 CPU и 4 ГиБ RAM;
- только порт **127.0.0.1:3310** на Windows-хосте; внутри Docker это порт 3310;
- отдельный Docker-volume только для баз сигнатур `/var/lib/clamav`;
- **никаких bind-mount** хранилища пациента, секретов PostgreSQL и исходного кода;
- `restart: no`; исходное приложение не зависит от состояния контейнера.

Docker Desktop должен иметь достаточный **общий запас памяти сверх 4 ГиБ**
для PostgreSQL и системы. Запуск только на синтетических тестовых данных.
Если официальный образ не запускается с указанными непривилегированными
ограничениями, **не удалять ограничения вслепую**. Зафиксировать логи
без персональных данных и отдельно согласовать корректировку.

## PowerShell: предварительная проверка и запуск

Команды из корня проекта, с активированным `.venv`:

```powershell
# Проверить текущие сервисы и конфигурацию, без запуска ClamAV:
docker compose -f compose.yaml -f compose.av.yaml --profile av config -q
docker compose -f compose.yaml -f compose.av.yaml --profile av config

# Убедиться, что на 3310 нет чужого процесса:
Get-NetTCPConnection -LocalPort 3310 -State Listen -ErrorAction SilentlyContinue

# Только если пользователь осознанно разрешил загрузку официального Docker-образа:
docker compose -f compose.yaml -f compose.av.yaml --profile av up -d clamd

# Дождаться состояния healthy и загрузки сигнатур:
docker compose -f compose.yaml -f compose.av.yaml --profile av ps
docker compose -f compose.yaml -f compose.av.yaml --profile av logs --tail 60 clamd

# Только синтетический стандартный AV-тест, без медицинских файлов:
$env:PYTHONPATH = (Resolve-Path .\backend).Path
python -m app.workers.clamd_preflight --check-eicar
Remove-Item Env:PYTHONPATH

# После испытания остановить ТОЛЬКО ClamAV; не удалять volume с сигнатурами:
docker compose -f compose.yaml -f compose.av.yaml --profile av stop clamd
```

`Get-NetTCPConnection` должен вернуть **пустой результат до первого запуска**;
если уже есть слушатель, выяснить его владельца. При запущенном ClamAV порт
должен соответствовать контейнеру с ожидаемым образом. Docker Desktop
и Windows Firewall следует проверять отдельно — loopback-привязка сама по
себе не доказывает, что соединение нельзя перехватить локальным процессом.

`--check-eicar` отправляет только тестовые 68 байт через старый
`ClamdScanner.scan()`. PASS возвращается только при ответе `FOUND`,
синтаксически валидной VERSION и дате сигнатур не старше 7 дней
(в VERSION время без суффикса трактуется как UTC). Exit code: 0 PASS,
1 FAIL, 2 неправильная команда. **`PASS` не означает, что ClamAV доверенный,
не удостоверяет источник сигнатур и не разрешает обработку вложений.**

Если EICAR-тест не обнаружен, ClamAV недоступен, сигнатуры устарели
или дата отличается от часов — **FAIL, обработка остаётся запрещённой**.
На Windows защитное ПО может реагировать на EICAR даже без файла;
скрипт не записывает сигнатуру на диск и не скачивает тестовые файлы.

не считать успешной проверкой.

## Архитектурные конфликты

1. **Владение и инварианты:** PostgreSQL ведёт статусы/аудит, локальное
   хранилище владеет байтами, а контейнер владеет *только* сигнатурами.
   Статус `clean_reported` не является разрешением на обработку.
2. **Контракты:** действующие HTTP-маршруты, миграции и схема БД сохранены.
   Диагностика запускается отдельно, без переменных окружения приложения.
3. **Эволюция:** для будущего CDR/парсеров потребуется собственная изоляция,
   источник достоверного статуса AV (не только текст по TCP),
   защита от смены байтов после сканирования, проверка актуальности базы
   непосредственно перед каждым допуском и запрет повторного использования
   устаревшего результата.

## Риски и ограничения

- Образ — сторонняя тяжёлая **опциональная** зависимость (~гигабайты памяти).
  Его загрузка требует сети, лицензионной и инфраструктурной оценки.
- `127.0.0.1` защищает от обычного внешнего сетевого доступа, **не от других
  локальных процессов**. ClamAV TCP не имеет аутентификации/шифрования.
- Контейнер не устраняет все уязвимости образа или Docker Desktop.
  Запуск на рабочей станции не является production-песочницей.
- EICAR — тест одной сигнатуры, не доказательство обнаружения других угроз.
- Дата версии заявляется сервером, а не проверяется криптографически.
- Docker Compose, реальный ClamAV, свежесть реальных баз и Windows ACL
  необходимо проверить вручную. Без проверки — нельзя считать 6.3.2 закрытым.
