# UI-6B — пользовательские кабинеты и проверки CI

## Назначение

Этот инкремент приводит три существующих кабинета к рабочему интерфейсу без
подписей внутренних этапов, сырого JSON медицинских событий, идентификаторов
снимков AI и пояснений о реализации сервера.

Изменения выполнены поверх присланного `AIDoctor.rar` от 23 октября 2026 года.
Существующие медицинские данные, API назначений и миграции сохраняются.

## Что видят пользователи

**Врач:** пациенты, визиты, история, наблюдения, назначения, психологические
опросники, клиническая сводка, AI-рабочая область и настройки. События истории
показываются с понятными подписями; исходные данные хранятся в БД без изменений.

**Пациент:** карточка, опубликованные врачом сведения, действующие утверждённые
назначения и назначенные опросники. Внутренние записи и AI-черновики пациенту
не раскрываются. Учебные шкалы остаются явно обозначены как невалидированные.

**Администратор:** управление пользователями, учебными карточками, врачебными
доступами, привязкой и аудитом. Функции создания реального пациента и удаления
медицинских данных этим инкрементом не добавляются.

**AI:** если модель не подключена, интерфейс не выдумывает ответ.
Тренировочное согласование доступно в интерфейсе только когда backend вернул
`synthetic_review_enabled=true`. Это возможно только при явном включении
режима и для синтетической карточки пациента; в `APP_ENV=production`
тренировочный импорт принудительно отключён.

## Архитектура и договорённости

- PostgreSQL остаётся источником истины.
- Разграничение данных врач–пациент остаётся на backend.
- Учебный AI-режим не заменяет LLM и не подтверждает клиническую безопасность.
- Новое поле API `synthetic_review_enabled` добавлено к `AIWorkspaceInfo`;
  старые поля сохранены.
- Миграции БД не требуются.
- Изменения интерфейса не дают новых прав и не изменяют назначений.

## Команды PowerShell

Из корня проекта с активированной `.venv`:

```powershell
python -m ruff check backend --fix
python -m ruff format backend
python -m ruff check backend
python -m ruff format --check backend
node --check backend/app/web/assets/app.js
python -m pytest backend/tests/test_ui6b_product_ui_unit.py backend/tests/test_ui6b_backend_unit.py backend/tests/test_ui4a_navigation_unit.py backend/tests/test_ui4b_clinical_ui_unit.py -v
python -m alembic -c alembic.ini check
```

Для полной регрессии используйте отдельную БД (тесты могут удалять таблицы):

```powershell
$env:TEST_DATABASE_URL = "postgresql+psycopg://aidoctor:aidoctor_dev@127.0.0.1:5432/aidoctor_test"
python -m pytest backend/tests -q -rs
Remove-Item Env:TEST_DATABASE_URL -ErrorAction SilentlyContinue
```

Запуск FastAPI:

```powershell
python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000 --reload
```

После установки обновите страницу с принудительным обновлением CSS/JS
(`Ctrl+F5`). Адрес: `http://127.0.0.1:8000/app`.

## GitHub Actions

Файл `.github/workflows/ci.yml` запускается на push / pull request, а также
вручную. В нём:

1. Проверки Python/Ruff и синтаксиса JavaScript.
2. Временный PostgreSQL 16, изолированные БД для миграций и тестов.
3. `alembic upgrade head` + `alembic check`.
4. Полный pytest на `aidoctor_test`.

CI ничего не выкладывает на ВМ, не использует `aidoctor` разработчика и не
имеет доступа к медицинским секретам. Настройки ВМ, HTTPS, политика резервного
копирования, защита секретов и производственное развёртывание — отдельный этап.

**Важно:** приложенный исходный RAR содержит `.env`, `.git` и `.venv`.
Перед публикацией GitHub убедитесь, что реальные секреты никогда не попадают
в коммиты. `.gitignore` не удаляет уже отслеживаемые файлы.

Проверить без раскрытия содержимого:
```powershell
git ls-files .env
git status --short
```

Если `.env` уже отслеживается Git, его исключение из репозитория и ротация
скомпрометированных секретов обязательны перед размещением кода в сети.

## Выполненные проверки этой поставки

- Python: синтаксис изменённых файлов проверен.
- JavaScript: проверен `node --check`.
- 8 структурных проверок трёх кабинетов и интерфейса согласования пройдены.
- Chromium без реальной БД (имитация ответов API): вход врача, пациента и
  администратора, доступность 9/4/5 пунктов меню соответственно, скрытие
  тренировочного AI, отсутствие ошибок JavaScript и горизонтального
  переполнения при ширине 390 px — пройдено.
- Полная интеграция с PostgreSQL и проверка клинических сценариев в этой
  среде не выполнялись; команды выше предназначены для локальной проверки.
- GitHub Actions будет проверен только после первого push в репозиторий.

## Ручная приёмка

1. Войти врачом. Проверить все девять пунктов меню и два пациента.
2. Открыть визиты, события и дополнительные сведения: нет JSON и технических ID.
3. Создать безопасный учебный черновик назначения; проверить диалог утверждения.
4. Войти пациентом: чужие медицинские сведения и врачебные черновики отсутствуют.
5. Пройти назначенный учебный опросник; результат обозначен не диагнозом.
6. Войти администратором: видны пользователи и связи без клинической истории.
7. Открыть AI-раздел: без LLM нет выдуманного ответа и нет кнопки создания
   тренировочных черновиков без явного включения соответствующего режима.
8. Проверить ширину окна 1440, 1024, 768 и 390 пикселей, навигацию и формы.

## Критерии готовности

- У всех ролей отображается только разрешённое меню.
- У врача и пациента нет этапных UI-меток и технических полей БД.
- Критические предупреждения и признаки невалидированных тестов сохранены.
- AI-режим безопасен по умолчанию.
- Три теста интерфейса и регрессионные тесты проходят.
- CI проходит на чистом checkout без подключения к локальной БД.

## Границы

Обновление не означает допуска к работе с реальными пациентами. Не проводились
медицинская валидация назначений, проверка РКИ, аудит по требованиям
медицинской информационной системы и полный приёмочный аудит эксплуатации.
