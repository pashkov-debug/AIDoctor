# DEPLOY-3 — постоянный HTTPS-доступ к тестовому AIDoctor

## Что меняется

Добавляется отдельный контейнер Caddy на сервер FirstVDS
`185.200.179.238`. Он публикует **только TCP 80 и 443**, автоматически
получает и продлевает TLS-сертификат для выбранного домена и направляет
запросы в существующий контейнер FastAPI (`app:8000`).

База `aidoctor_synthetic`, Docker-тома, учётные записи и миграции
**не создаются заново и не изменяются**. Порт FastAPI
`127.0.0.1:18080` остаётся доступен только на сервере или через
SSH-туннель как резервный способ входа.

Каждый следующий Push в `master` продолжает обновлять FastAPI через
уже установленный GitHub Actions. Caddy остаётся работающим, потому что
находится в том же Docker Compose-проекте и обращается к сервису по
имени `app`. **Изменения самого Caddyfile и Compose HTTPS после Push
нужно применять отдельно повторным запуском скрипта 01.**

В публичном тестовом стенде **только синтетические пациенты**.
Реальные медицинские сведения не загружать.

## Шаг 1. Windows / PyCharm

Распаковать ZIP в корень проекта, добавить новые файлы.

Проверить:

```powershell
python -m ruff check backend
python -m ruff format --check backend
python -m pytest backend/tests/test_deploy3_https_unit.py -q
node --check backend/app/web/assets/app.js
```

После проверки сделать Commit и Push в `master` **через PyCharm**.
Дождаться зелёного GitHub Actions. Без Push сервер не увидит новые файлы.

## Шаг 2. Настроить домен и DNS

Использовать свой домен или поддомен, который можно редактировать
в DNS-панели. Например, в панели своего домена создать:

- Тип: `A`
- Имя: `demo` (если нужен адрес `demo.ваш-домен.ru`)
- Значение: `185.200.179.238`

Не добавлять AAAA-запись, пока IPv6 не настроен и не проверен.
Если у имени уже есть ошибочные A/AAAA-записи — исправить.

**Серверное имя `pashkovnpc.clodocd.com` — только кандидат.**
Не доказано, что оно доступно в публичном DNS и что ты управляешь им.
Проверить на Ubuntu можно командой:

```bash
getent ahostsv4 pashkovnpc.clodocd.com
```

Если вернётся `185.200.179.238`, можно попробовать включить HTTPS
именно с этим именем. Для долгосрочного адреса презентации лучше
использовать собственный управляемый домен. Не использовать `psihologpashkov.ru` по умолчанию.

Caddy выпустит доверенный публичный сертификат только при корректном
DNS и доступных портах 80/443. Временный туннель для этого не требуется.

## Шаг 3. Аудит firewall на Ubuntu

Подключиться:

```powershell
ssh root@185.200.179.238
```

Далее команды **в Ubuntu**:

```bash
cd /opt/aidoctor/git-checkout
bash deploy/https/00_firewall.sh
```

Из предыдущего smoke-test известно, что UFW разрешал FTP, почту, DNS
и ispmanager. Если это выделенный VDS **только для AIDoctor** и другие
службы не используются, выполнить:

```bash
bash deploy/https/00_firewall.sh --apply
```

Команда сохраняет SSH (22/tcp), открывает 80/tcp и 443/tcp и
удаляет известные лишние разрешения UFW. При неожиданных правилах
скрипт завершится с ошибкой и потребует ручной проверки.

**Не применять --apply, если через этот сервер действительно
работают почта, FTP, DNS или ispmanager.** Не прерывать текущий SSH.
Docker способен обходить UFW для опубликованных контейнерных портов,
поэтому Docker Compose публикует только 80/443 для Caddy, а
PostgreSQL вообще не публикует порты.

## Шаг 4. Включить HTTPS

На VDS (после успешного Push):

```bash
cd /opt/aidoctor/git-checkout
bash deploy/https/01_enable_https.sh ИМЯ_ВАШЕГО_ДОМЕНА
```

Например, если управляемый домен действительно настроен:
`bash deploy/https/01_enable_https.sh demo.example.com`
(примерный адрес **нужно заменить** на собственный настоящий).

Повторный запуск с тем же доменом перезапускает **только Caddy**
для применения обновлённого Caddyfile и не пересоздаёт FastAPI/БД.

Скрипт перед запуском проверяет DNS — он обязан указывать ровно
на IPv4 `185.200.179.238`, без неподдерживаемой AAAA-записи.
Проверяет UFW, занятость 80/443 и синтаксис Caddyfile.
При ошибке останавливается, не трогая существующую БД.

Домен записывается в `/opt/aidoctor/https.env` с правами `0600`
**вне Git**. Сертификаты Caddy хранятся в отдельных Docker-томах.

После успешного запуска открыть в любом браузере:

`https://ИМЯ_ВАШЕГО_ДОМЕНА/app`

PowerShell и SSH-туннель для обычного входа уже не нужны.

## Шаг 5. Проверить

На Ubuntu:

```bash
bash /opt/aidoctor/git-checkout/deploy/https/02_check_https.sh
```

Должно быть: HTTPS `/app` возвращает 200, `/docs` возвращает 404,
локальный API сообщает `test/ok`, PostgreSQL без опубликованного порта.

В другом устройстве/браузере проверить реальный HTTPS и авторизацию
в трёх кабинетах. Проверять только на синтетических данных.
Наличие сертификата ещё не подтверждает защиту всех API.

## Экстренно отключить публичный сайт

На Ubuntu:

```bash
bash /opt/aidoctor/git-checkout/deploy/https/03_stop_https.sh
```

Останавливается **только Caddy**; база, FastAPI, Docker-тома и
HTTPS-сертификаты сохраняются. Прежний SSH-туннель остаётся доступным.

Для последующего включения повторно выполнить `01_enable_https.sh`
с тем же доменом.

## Границы и риски

- Это **публичный демостенд**, не production с реальными пациентами.
- Вход пользователей по-прежнему обеспечивается FastAPI. В текущем коде
  не подтверждён отдельный rate limiting для HTTP-входа. До реальной
  медицинской эксплуатации необходим аудит защиты от перебора,
  контроля сессий, журналирования и персональных данных.
- Публичный адрес не означает, что медицинский AI уже подключён.
- Не запускать `docker compose down -v` и не переинициализировать seed.
- Проверь дату оплаченного VDS и продление тарифа, чтобы презентация
  не прервалась из-за отключения сервера.
- Автодеплой FastAPI остаётся автоматическим. Изменения **инфраструктуры
  HTTPS** применяются отдельной командой `01_enable_https.sh`.
- Правила UFW не заменяют проверку фактически слушающих сетевых служб.

## Интеграции / конфликты

1. **Владение данными:** PostgreSQL — единственный источник истины.
   Caddy не получает пароль БД и не выполняет SQL, однако на этом
   тестовом стенде находится в той же Docker-сети; перед production
   сеть прокси и базы требуется развести.
2. **Контракты:** FastAPI и API не меняются; HTTPS-прокси передаёт
   существующие маршруты `/app` и `/api/v1`.
3. **Эволюция:** AI Gateway позже подключается через отдельные
   проверенные API-контракты, не через прямой доступ к PostgreSQL.
4. **Откат:** остановка Caddy не откатывает миграции; GitHub
   продолжает хранить историю кода, а резервные копии — историю БД.
