# UI-4B — поэлементное согласование синтетического черновика

## Область применения

Эта поставка реализует **проверяемое согласование учебных структурированных предложений**.
Настоящий AI/LLM не вызывается. Любой импорт имеет `origin=synthetic_manual_test`,
`schema_version=ai_review.v1`, а источники не подтверждены.

Для доступа необходимы:
1. действующая учётная запись с ролью `doctor` и связь с пациентом;
2. `demographics_json.synthetic == true` у выбранного пациента;
3. переменная окружения `AIDOCTOR_ALLOW_SYNTHETIC_AI_DRAFTS=1` в процессе FastAPI.

В настоящем окружении переменная **должна оставаться равной 0**.
Синтетические предложения никогда не проходят автоматическую научную или
фармакологическую экспертизу.

## Установка поверх UI-4A NAV

Распаковать ZIP из корня проекта с заменой перечисленных файлов.
Не удалять данные и PostgreSQL volume.

В PowerShell из корня AIDoctor:

```powershell
docker compose up -d postgres
docker compose exec postgres pg_isready -U aidoctor -d aidoctor
python -m alembic -c alembic.ini upgrade head
python -m alembic -c alembic.ini check
python -m ruff check backend --fix
python -m ruff format backend
python -m ruff check backend
python -m ruff format --check backend
node --check backend/app/web/assets/app.js
$env:PYTHONPATH = "backend"
python -m pytest backend/tests/test_ui4b_unit.py backend/tests/test_ui4b_clinical_ui_unit.py -v
$env:TEST_DATABASE_URL = "postgresql+psycopg://aidoctor:aidoctor_dev@127.0.0.1:5432/aidoctor_test"
python -m pytest backend/tests/test_ui4b_pg.py -v -rs
python -m pytest backend/tests -q -rs
Remove-Item Env:TEST_DATABASE_URL -ErrorAction SilentlyContinue
```

Для локального ручного теста в **другом терминале** включить учебный режим:

```powershell
$env:AIDOCTOR_ALLOW_SYNTHETIC_AI_DRAFTS = "1"
python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000 --reload
```

Если FastAPI уже запущен, его надо перезапустить с этой переменной.
Для последующего обычного запуска убрать переменную:

```powershell
Remove-Item Env:AIDOCTOR_ALLOW_SYNTHETIC_AI_DRAFTS -ErrorAction SilentlyContinue
```

## Проверка интерфейса

1. Врач `doctor_ui1` → «Рабочая область AI» → пациент С-001 → сохранить вопрос.
2. В истории запросов нажать «Открыть согласование».
3. «Создать учебный структурированный черновик». Появятся условные препараты
   А и Б (взаимоисключающие), обследование и учебный опросник.
4. Выбрать один препарат и обследование; раскрыть поля, исправить длительность,
   записать причину, нажать «Проверить выбранные назначения».
5. Сверить исходное предложение и итоговое назначение на понятных врачу полях:
   препарат, доза, способ, время, продолжительность, противопоказания и источники.
   Изменённые поля подсвечены; пациент увидит только утверждённое.
6. Нажать «Утвердить выбранное» и подтвердить действие.
7. Пациент видит **только утверждённые** назначения; тест — в списке тестов.
8. Для проверки отклонения создать второй подготовленный запрос и отклонить
   черновик с причиной — записи не должны добавиться.

## Публичные контракты

- `GET /patients/{patient_id}/ai-requests/{request_id}/review`
- `GET /patients/{patient_id}/ai-requests/{request_id}/review/versions/{version}` — неизменяемая историческая версия.
- `POST /patients/{patient_id}/ai-requests/{request_id}/review` — импорт первой/
  следующей ручной версии с `expected_version`.
- `POST /patients/{patient_id}/ai-requests/{request_id}/review/preview`
- `POST /patients/{patient_id}/ai-requests/{request_id}/review/approve`
- `POST /patients/{patient_id}/ai-requests/{request_id}/review/reject`

Префикс маршрутов `/api/v1`. Все маршруты доступны лишь уполномоченному врачу
и только для синтетической карточки в разрешённом режиме. Ответы содержат
`Cache-Control: private, no-store`.

Источником истины остаётся PostgreSQL. Версии `ai_review_versions` неизменяемы,
решения — в `ai_review_events`, создаваемые назначения — в нормализованных
`clinical_orders` и `questionnaire_assignments` с собственным аудитом.

Критически важное ограничение: Preview — **серверный** расчёт итоговых записей,
подписанный контрольной суммой; commit повторно пересчитывает payload, версию,
актуальный Context Builder, настройки врача и текущие назначения/тесты.
При изменении условий возвращается HTTP 409. Commit делает все операции одной
транзакцией, без промежуточной публикации. Препараты из одной группы
`alternative_group` вместе утвердить нельзя.

## Ограничения

- Только учебные предложения, без OpenAI/MCP/LLM.
- Никакой проверки научной достоверности доз, противопоказаний и источников.
- Никаких реальных пациентов.
- Контекст привязан к версии запроса, а сами исходные вложения не передаются.
- Автоматическое назначение без явного врача исключено.
- Сценарий рассчитан на проверку workflow перед подключением настоящей модели.

## Интеграция и риски

- Клиническая логика остаётся на backend; frontend лишь редактирует и подтверждает.
- Роли и клинические записи используют уже существующие контракты.
- Неизменяемая история версий позволяет добавить реальный LLM Gateway позже.
- PostgreSQL-интеграционные тесты допускаются **только** для `aidoctor_test`.

## Отображение данных врачу и технический контракт

Врач не видит названия таблиц, SQL, JSON, идентификаторы записей или контрольные суммы
в окне подтверждения. Для каждого выбранного предложения показываются клинические
поля и сравнение с исходным учебным вариантом. Система явно предупреждает,
что после утверждения назначения будут доступны пациенту.

В backend контракт **не изменён**: `preview_sha256`, версия запроса, проверка
полномочий, атомарная запись, аудит и HTTP 409 при устаревшем просмотре остаются
обязательными. Информация об отсутствии медицинской проверки дозировок
также остаётся на экране врача.

Сверка формата полей не подтверждает клиническую правильность назначения.
