# AIDoctor — этап 5.1: ручные сигналы безопасности

**Статус:** экспериментальный backend MVP на синтетических данных.
Никаких автоматических диагнозов, клинических порогов, LLM-вызовов и доставки уведомлений.

## Сценарий

Врач или администратор, имеющий доступ к пациенту, вручную создаёт сигнал
о необходимости проверки. Создание записывает `safety_alerts` и событие
`safety_alert_events(created)` в одной транзакции. Подтверждение
`ack` меняет статус на `acknowledged` и добавляет событие
`acknowledged` атомарно; при повторном запросе статус и журнал не изменяются.

| API | Права |
|---|---|
| `POST /api/v1/patients/{id}/safety-alerts` | Врач с привязкой или администратор |
| `GET /api/v1/patients/{id}/safety-alerts` | Те же |
| `POST /api/v1/patients/{id}/safety-alerts/{alert_id}/ack` | Те же |

Тело POST:

```json
{"reason_code": "clinician_review", "priority": "standard"}
```

Допустимые коды: `clinician_review`, `care_coordination`, `urgent_attention`.
Приоритет: `standard` или `urgent`. Приоритет выставляет врач, не алгоритм.

Ответ содержит `delivery_status = "not_configured"`. **Сообщение никому
автоматически не отправляется**, интерфейс не должен показывать «доставлено».
`ack` означает лишь подтверждение просмотра, не выполнение медицинских действий.

## Безопасность

- HTTP `401` при отсутствии bearer, `404` чужому врачу, `403` пациенту.
- Проверка прав выполняется **до проверки тела** POST.
- Модели находятся в PostgreSQL, журнал не удаляется и не редактируется через API.
- Журнал сейчас не защищён от прямого изменения администратором PostgreSQL;
  называть его юридически неизменяемым нельзя.
- Миграция `aisafe_v1_20261017`, родитель `aictx_v3_20261017`.
- Автоматический downgrade запрещён для сохранения истории действий.
- Нет журнала чтения медданных, поддержки retention, TLS, антивируса и
  реального механизма доставки/повторных попыток.
- Не использовать в чрезвычайной ситуации: требуются действующие каналы экстренной помощи.

## Локальная проверка

```powershell
python -m alembic -c alembic.ini current
python -m alembic -c alembic.ini upgrade head
python -m alembic -c alembic.ini check
python -m ruff check backend
python -m pytest backend/tests/test_safety_alert_schema.py -v
python -m pytest backend/tests/test_safety_alerts_api.py -v -rs
python -m pytest backend/tests -v -rs
```

Отсутствие `TEST_DATABASE_URL` => PostgreSQL-тесты `SKIPPED`, а не `PASSED`.
