# UI-6A — контекст для проверки проектов назначений агентом

## Назначение

Цель инкремента — передавать **при последующем разрешённом подключении AI**
реальные структурированные сведения о лекарствах, назначениях и врачебных
черновиках. Это не подключение к ChatGPT, MCP или OpenAI API.

Вопрос врача сохраняется с тремя независимыми составляющими:

1. `patient_context`: неизменяемый контекст пациента из `Context Builder 1.0`;
2. `doctor_context`: клинические настройки врача (РКИ — российские клинические
   рекомендации Минздрава РФ), сохранённые на момент запроса;
3. `orders_review`: утверждённые назначения `approved_orders` и
   **отдельные неутверждённые** `proposed_orders_for_review`.

В проектных назначениях сохраняются препарат, действующее вещество,
доза и единица, кратность, время, часовой пояс, даты, обоснование, источник,
версия, статус и идентификатор записи. Сообщённые пациентом лекарства
из клинической истории остаются историческими фактами с указанием происхождения,
а не превращаются в утверждённую терапию.

`clinical_safety_validated=false` — наличие структурированных полей не
подтверждает безопасность. **Никаких проверочных ответов об ошибках дозы или
взаимодействиях в контекст не добавляется.**

## Интерфейс backend

```http
GET /api/v1/patients/{patient_id}/ai-requests/{request_id}/agent-context
```

Только авторизованный врач, имеющий доступ к пациенту и создавший запрос.
Заголовок `Cache-Control: private, no-store`.

Новые запросы сохраняют `review_orders_json` и `review_orders_sha256`
**в одной транзакции** с исходным пациентским snapshot и записью аудита.
Снимок никогда не пересчитывается при его чтении: изменение исходного
черновика не меняет ранее сохранённый запрос.

При несоответствии контрольной суммы — HTTP 409.
Если запрос был создан до UI-6A, он остаётся доступным в обычной истории
UI-4A, но новый endpoint возвращает **409 и предлагает создать новый запрос**.
Сведения задним числом не дорисовываются.

Новые дополнительные поля таблицы `ai_requests` допускают NULL для
старых запросов. Миграция: `ui6a_20261023`.

В UI-4B при проверке и утверждении теперь дополнительно сравнивается
сохранённый перечень назначений с актуальным; при расхождении — HTTP 409
и требуется новый AI-запрос. Старые запросы продолжают использовать
прежний контроль доступных версий, без фиктивного восстановления снимка.

Отменённые назначения не входят в блок текущих утверждённых и
предложенных записей; если после подготовки запроса назначение отменено,
на последующей проверке изменение выявится.

## Границы и безопасность

- LLM-вызов и внешняя отправка **выключены**; `llm_dispatch_enabled=false`.
- Содержимое файлов, включая карантинные вложения, в контекст не попадает.
  Их метаданные имеют отдельное поле `excluded_attachments`.
- Максимум 100 активных/проектных назначений и 256 КиБ этого блока.
  Превышение запрещает создать запрос, а не обрезает клинически важные записи.
- **Исходная терапия и новые проекты никогда не смешиваются.**
- Клинические ответы AI, лекарства и дозировки не появляются автоматически.
  Врач по-прежнему утверждает конкретные элементы через backend UI-4B.
- Контракт не предназначен для медицинской практики с реальными данными
  без дополнительной проверки безопасности, согласия, актуальности источников
  и законных оснований обработки данных.
- Не проверяются внешняя безопасность препарата, актуальные рекомендации,
  лекарственные взаимодействия и полная согласованность транзакций
  при конкурентных изменениях пациента. Последнее проверяется в UI-6B.

## Установка — PowerShell в корне AIDoctor

```powershell
docker compose up -d postgres
docker compose exec postgres pg_isready -U aidoctor -d aidoctor
python -m alembic -c alembic.ini upgrade head
python -m alembic -c alembic.ini check
```

## Исправление стиля, форматирование, тесты

```powershell
python -m ruff check backend --fix
python -m ruff format backend
python -m ruff check backend
python -m ruff format --check backend

$env:PYTHONPATH = "backend"
python -m pytest backend/tests/test_ui6a_unit.py -v

$env:TEST_DATABASE_URL = "postgresql+psycopg://aidoctor:aidoctor_dev@127.0.0.1:5432/aidoctor_test"
python -m pytest backend/tests/test_ui6a_pg.py -v -rs
python -m pytest backend/tests -q -rs
Remove-Item Env:TEST_DATABASE_URL -ErrorAction SilentlyContinue
```

**Запрещено запускать integration-тесты на основной `aidoctor`: тестовая
фикстура удаляет и создаёт SQL-таблицы.** Основная локальная БД с
постоянными синтетическими пациентами не пересоздаётся.

Запуск:

```powershell
python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000 --reload
```

## Критерии готовности

1. Применена миграция, старые запросы не потеряны.
2. Новый запрос фиксирует обе группы назначений и версию каждой.
3. UI-5 черновики не выглядят утверждёнными и не видны пациенту.
4. Старый запрос нельзя автоматически обогатить новыми назначениями.
5. Врач с другим доступом, пациент и администратор не получают пакет.
6. Снимок не переписывается после корректировки дозы; контроль изменений
   блокирует утверждение со старым клиническим контекстом.
7. Ruff, тесты и Alembic проходят локально.
