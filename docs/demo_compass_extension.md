# AIDoctor — сценарий «Клинический компас» (дополнительный инкремент)

> ВНИМАНИЕ: тестовый медицинский сценарий. Только синтетические данные.
> Не предназначено для невалидированного назначения лечения реальным пациентам.

## Что входит в архив

- Совместимый с Site Builder v2 **дополнительный** API `POST /api/v1/integrations/site-builder/v2/structured-proposals`.
- `aidoctor_structured_proposals.v1`: полные типизированные предложения (история, наблюдения, обследования, препараты).
- Неподменяемая принадлежность: тот же ключ врача, тот же `request_id`, `patient_id`, 3 SHA-256, существующий неизменяемый анализ.
- Поэлементное review и действующие механизмы предпросмотра, подтверждения и аудита.
- Независимая детерминированная проверка неправильного режима Авиандр (не представляет собой вывод AI).
- Баннер безопасности в рабочем месте врача и ссылка на источник инструкции.
- Дополнительный `--without-medication-draft` для импорта: можно дать AI предложить препарат, не дублируя стартовый черновик из DOCX.

## Как получить настоящие структурированные предложения существующего агента

1. В AIDoctor создать AI-запрос конкретного врача/пациента.
2. В агенте «Для Тани» получить контекст через существующий MCP Site Builder v2.
3. В том же агенте вызвать существующий `submit_demo_analysis` (сохранить общий анализ).
4. В конфигурации **этого же агента**, не создавая второго, подключить дополнительную операцию:
   `POST /api/v1/integrations/site-builder/v2/structured-proposals`
   с действующим заголовком `X-AIDoctor-Doctor-Key`.
5. Агент отправляет `StructuredProposalSubmit`:
   - `schema_version = "aidoctor_structured_proposals.v1"`
   - `request_id`, `patient_id`
   - `context_sha256`, `orders_sha256` из исходного контекста
   - `analysis_payload_sha256` из ответа после сохранения AI-анализа
   - `proposals` — массив `Proposal` (типовые модели `ai_review.v1`, с `evidence_status="unverified_ai"`).
6. Врач в AIDoctor открывает review текущего запроса, проверяет каждое предложение, сравнивает поля и подтверждает только подходящее.

**Без пункта 4** инструмент от агента не появится сам по себе. Не изображать заранее введённые текст и дозировку как результат живой генерации. Записанный ранее ответ можно показывать только как «Сохранённый тестовый AI-анализ».

## Видео: сцены

### Сцена А — AI готовит структурированную историю и назначения

- Пациентка создана по DOCX на 0-й неделе, без стартового лекарственного черновика.
- Врач задаёт вопрос на дополнение истории и лечебного плана с ссылками на инструкции и клинические рекомендации.
- Агент **фактически** отправляет структурированные поля (не текст для ручного копирования).
- UI показывает `site_builder_structured_v1` и подтверждение «получены типизированные предложения».
- Врач принимает часть предложений; данные появляются в существующих медицинских таблицах и аудите.

### Сцена Б — врач ошибся, AI предупредил

- Врач создаёт отдельный черновик препарата Авиандр 40 мг 2 раза в сутки (80 мг/сут) **как заведомо ошибочный тестовый ввод**, без утверждения.
- AIDoctor сразу выводит предупреждение **детерминированной** проверки (сравнение с режимом 20 мг 2 раза в сутки при ГТР).
- Новый AI-запрос должен быть создан **после сохранения ошибочного черновика**, иначе хеш контекста устареет.
- Агент видит черновик, передаёт лекарственный риск в `medication_risks`, с аргументами и источником.
- Врач исправляет ошибочный черновик и только затем может рассматривать вопрос об утверждении.
- Не утверждать ошибочное назначение ради видео. После редактирования создать новый AI-запрос: старый снимок устарел.

Оговорка безопасности: перечисленные нежелательные реакции — возможные, не предсказанный исход превышения дозы для данного пациента. В прикладной системе нет полномасштабного движка проверки взаимодействий.

## Проверить четвёртую пациентку на тестовом Ubuntu VDS

Не запускать импорт в production-базу. Импорт умеет писать только в `APP_ENV=test`, `aidoctor_synthetic`.

```bash
cd /opt/aidoctor/git-checkout
DC='docker compose --env-file .env.test -f deploy/compose.test.yaml'
$DC ps
$DC exec -T app python -m backend.scripts.seed_aviandr_case --check --through-week 0 --without-medication-draft
$DC exec -T postgres psql -U aidoctor -d aidoctor_synthetic \
  -c "SELECT username FROM users WHERE role='doctor' ORDER BY username;"
```

Перед записью сделать резервную копию:

```bash
mkdir -p "$HOME/aidoctor_backups"
docker compose --env-file .env.test -f deploy/compose.test.yaml exec -T postgres \
  pg_dump -U aidoctor -d aidoctor_synthetic -Fc \
  > "$HOME/aidoctor_backups/aidoctor_before_demo_$(date +%Y%m%d_%H%M%S).dump"
```

Начальная неделя для сюжета «AI предлагает»:

```bash
docker compose --env-file .env.test -f deploy/compose.test.yaml exec -T app \
  python -m backend.scripts.seed_aviandr_case --apply --doctor doctor_ui1 \
  --through-week 0 --without-medication-draft
```

После завершения видеосцен с AI-дозировками можно наполнить всю динамику:

```bash
docker compose --env-file .env.test -f deploy/compose.test.yaml exec -T app \
  python -m backend.scripts.seed_aviandr_case --apply --doctor doctor_ui1 \
  --through-week 8 --without-medication-draft
```

**Важно:** после добавления визитов старый AI-запрос теряет актуальность. Для новых ответов нужен новый запрос.

Проверка:

```bash
docker compose --env-file .env.test -f deploy/compose.test.yaml exec -T postgres \
  psql -U aidoctor -d aidoctor_synthetic \
  -c "SELECT alias, demographics_json->>'synthetic' AS demo FROM patients WHERE deleted_at IS NULL ORDER BY alias;"
```

Если пациент не виден: проверить, что вошли именно под тем врачом, которому пациент привязан, и что код с импортом есть в контейнере. Повторно не инициализировать базовую БД.

## Ограничения

- Новая операция MCP требует ручного добавления в существующий коннектор/агент; сайт не запускает ChatGPT автоматически.
- Нельзя обещать, что AI подготовил текст или дозировку, если соответствующий POST не был фактически выполнен тем же агентом.
- Проверка препарата — ограниченное учебное правило для Авиандр при ГТР; не полноценная фармакологическая валидация.
- Требования PDF по двусторонней коммуникации, приверженности, экстренным уведомлениям, автоматизированной маршрутизации к психиатру и соблюдению права РФ требуют отдельных end-to-end проверок и не объявляются выполненными этой надстройкой.
- Нет проверки развёртывания на действующей PostgreSQL и VDS в этом пакете.
