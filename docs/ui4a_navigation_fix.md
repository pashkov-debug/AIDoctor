# UI-4A/NAV — исправление отображения AI и боковое меню

Устанавливать **поверх UI-4A**. Архив содержит только полные
изменённые файлы; распаковывать в корень AIDoctor, разрешив замену.
PostgreSQL не пересоздавать. Миграций нет.

## Видимость разделов

- **Врач:** слева выбор пациента и девять пунктов меню:
  пациенты, визиты, история, наблюдения, назначения,
  психологические тесты, Context Builder, AI, настройки.
- **Пациент:** личная карточка, записи врача, утверждённые
  назначения, назначенные тесты.
- **Администратор:** пользователи, карточки, связи,
  привязка аккаунта, аудит.
- Только один подраздел активен в области справа.
- Без выбранного пациента клинические разделы выводят приглашение
  выбрать пациента, вместо попытки загрузки чужих записей.
- Кнопка AI видима доктору даже до выбора пациента. На странице AI
  выбор пациента сохраняется; внешний AI-провайдер не вызывается.

## PowerShell (корень проекта, активна .venv)

Проверить миграции при запущенном PostgreSQL (новых нет):

```powershell
python -m alembic -c alembic.ini current
python -m alembic -c alembic.ini check
```

Ruff и форматирование:

```powershell
python -m ruff check backend --fix
python -m ruff format backend
python -m ruff check backend
python -m ruff format --check backend
node --check backend/app/web/assets/app.js
```

Быстрые тесты навигации (без БД):

```powershell
python -m pytest backend/tests/test_ui4a_navigation_unit.py -v
```

Регрессия только на выделенной тестовой БД:

```powershell
$env:TEST_DATABASE_URL = "postgresql+psycopg://aidoctor:aidoctor_dev@127.0.0.1:5432/aidoctor_test"
python -m pytest backend/tests -q -rs
Remove-Item Env:TEST_DATABASE_URL -ErrorAction SilentlyContinue
```

Запуск FastAPI:

```powershell
python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000 --reload
```

Перейти на http://127.0.0.1:8000/app и один раз нажать Ctrl+F5,
чтобы обновить старые статические файлы.

## Ручной smoke

1. Войти как `doctor_ui1`: слева виден пункт «Рабочая область AI».
2. Нажать его: справа отдельный экран с тремя панелями
   (вопрос, вложения, ответ). «Отправить AI» отключена.
3. Выбрать пациента в боковом меню. Нажать «Визиты»,
   затем «Назначения»: второй экран не содержит визитов.
4. Перейти в кабинет `patient_ui1`: врачебные пункты отсутствуют,
   опубликованные сведения и назначения открываются отдельно.
5. Войти `admin_ui1`: отдельные пункты пользователей, связей и аудита.
6. Перезагрузить страницу: потребуется новый вход (токен в памяти).

## Границы и риски

Доработан только интерфейс; API, ORM, миграции и медицинская логика
не изменены. Настоящая причина прежней невидимости AI на машине
пользователя не подтверждена; версия статических файлов исключает
один из распространённых вариантов — устаревший JS/CSS из кэша.

**Владение данными:** PostgreSQL, серверные проверки доступа сохранены.
**Контракты:** существующие API, ID форм и событий не меняются.
**Эволюция:** новые разделы добавляются парами
`data-view + data-panel` и `data-panel-group + data-panel`.

Клинические данные доступны только авторизованным ролям по API,
не по состоянию меню. Права обязательно перепроверять на backend.
