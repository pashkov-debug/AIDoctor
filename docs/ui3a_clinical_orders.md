# UI-3A: назначения врача (локальный инкремент)

## Контракт и источник истины

- `clinical_orders` — один типизированный объект назначения (препарат/обследование),
  одно назначение на запись. SQL-колонки по данным препарата/обследования,
  `times_local` — JSON-массив строк ЧЧ:ММ, `timezone` — пояс IANA.
  `request_key` уникален вместе с автором для защиты от повторного POST.
- `clinical_order_audit` — неизменяемые снимки каждой версии после
  `draft_created`, `draft_updated`, `approved`, `cancelled`.
- `draft` → `approved` → `cancelled`; черновик допускает также отмену.
  Исправлять опубликованные назначения нельзя: отмените и создайте новый черновик.
  Неактуальные назначения не удаляются из БД.
- AI/LLM не подключены; `source_reference` — ручная метка, не проверенный сервисом источник.
- Роль `doctor` и действующая связь с живой карточкой проверяются в backend.
  Администратор не может ни утверждать, ни видеть врачебные назначения.
- Пациент получает `GET /api/v1/patients/me/clinical-orders` по токену,
  без выбора `patient_id`; только `status='approved'` и публичный allowlist.
- Структурная проверка времени/единиц/положительной дозы не устанавливает
  клиническую допустимость дозировки или лекарственных взаимодействий.
  Не использовать реальные данные до самостоятельного клинического аудита.

## API

| HTTP | Маршрут | Назначение |
|---|---|---|
| POST | `/api/v1/patients/{id}/clinical-orders` | Идемпотентное создание черновика |
| GET | `/api/v1/patients/{id}/clinical-orders` | Список врача |
| PUT | `/api/v1/patients/{id}/clinical-orders/{order_id}` | Изменение автором черновика с `expected_version` |
| POST | `/api/v1/patients/{id}/clinical-orders/{order_id}/approve` | Утверждение конкретной записи, двумя явными подтверждениями |
| POST | `/api/v1/patients/{id}/clinical-orders/{order_id}/cancel` | Отмена с причиной и версией |
| GET | `/api/v1/patients/me/clinical-orders` | Только активные утверждённые назначения своего пациента |

Статус 409: конкурирующая правка, устаревшая версия, повторный ключ с другим
телом или недопустимое изменение статуса. Статус 422: ошибки структуры,
неполные поля для утверждения. Если не хватает дозы или времени — черновик,
а не фиктивное заполнение. Одно утверждение означает публикацию **одной** записи.

## План тестирования (PowerShell)

Из корня проекта:

```powershell
docker compose up -d postgres
python -m alembic -c alembic.ini upgrade head
python -m alembic -c alembic.ini check
python -m ruff check backend --fix
python -m ruff format backend
python -m ruff check backend
python -m ruff format --check backend
node --check backend/app/web/assets/app.js

python -m pytest backend/tests/test_ui3a_pg.py -v -rs
python -m pytest backend/tests -q -rs
```

автоматические тесты с пересозданием таблиц на ней запускать нельзя.

Запуск сервера:

```powershell
python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000 --reload
```

## Сценарий ручной проверки

1. В `doctor_ui1` откройте С-001, раздел «Назначения».
2. Создайте черновик обследования с синтетическим названием, целью и
   обоснованием. Убедитесь, что пациент не видит его.
3. Нажмите «Просмотр изменений → Одобрить», проверьте полный перечень,
   подтвердите. Войдите как `patient_ui1`: появится только это обследование.
4. Врач отменяет с причиной: запись перестаёт быть актуальной пациенту.
5. Проверьте создание неполного черновика препарата: сервер должен
   отказать в утверждении с HTTP 422 без выдумывания дозы/времени.
6. Проверьте изоляцию второй карточки, отказ врачу без связи и роль admin.

## Конфликты и расширяемость

- Владение: автор редактирует черновик; утверждение — только врач с
  действующим доступом; PostgreSQL хранит историю версий и аудит.
- Контракты: новые маршруты/таблицы без изменения существующих клинических
  сущностей, Content Builder и Safety Alerts.
- Эволюция: AI-4B будет предлагать структурированные элементы через отдельный
  AI-черновик; нельзя напрямую писать в `clinical_orders` без врача.
  Для назначения психологического теста нужен отдельный каталог/протокол UI-3B.
- Границы: частота только с фиксированными часами, нет PRN, титрации,
  курсов с паузами, расчёта по массе, автоматической клинической проверки,
  контроля национальных клинических рекомендаций.
