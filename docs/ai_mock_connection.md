# AIDoctor — локальная симуляция соединения с AI

## Назначение

Два Python-процесса локально проверяют транспортный маршрут:

`FastAPI → авторизованный подготовленный AI-запрос → agent-context.v1 → технический SHA-256 → локальный HTTP MOCK → подтверждение`

**Симулятор НЕ является AI/LLM.** Он не обрабатывает медицинский текст, не возвращает диагнозов,
не проверяет лекарственные взаимодействия, не создаёт AI-черновиков и не утверждает назначения.
Клинический контекст остаётся внутри процесса тестового клиента AIDoctor;
имитатору передаются только версия, ID запроса, контрольная сумма и количество назначений.
Никакие документы, пароли и Bearer-токены имитатору не передаются.

## Предусловия

- Выполнены предыдущие миграции AIDoctor, PostgreSQL запущен.
- Врач `doctor_ui1` имеет доступ минимум к одному пациенту с `demographics.synthetic=true`.
- Все процессы работают на одной Windows-машине. Сервисы слушают только `127.0.0.1`.
- Нет необходимости в OpenAI API, ChatGPT Plus, облаке или установке библиотек.
- Нет изменений схемы БД и не требуется включать `AIDOCTOR_ALLOW_SYNTHETIC_AI_DRAFTS`.

## PowerShell — три терминала

Из корня проекта с активной `.venv`.

Терминал 1:

```powershell
docker compose up -d postgres
python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000 --reload
```

Терминал 2:

```powershell
python -m scripts.mock_ai_server
```

Терминал 3:

```powershell
python -m scripts.smoke_ai_connection
```

По умолчанию используется `doctor_ui1`, выбирается первый доступный синтетический пациент,
а последний подходящий AI-запрос переиспользуется. Если его нет, будет создан один новый
сохранённый запрос. Для нового актуального снимка:

```powershell
python -m scripts.smoke_ai_connection --fresh
```

Чтобы выбрать конкретного пациента:

```powershell
python -m scripts.smoke_ai_connection --patient-id "UUID_ПАЦИЕНТА"
```

Скрипт спросит пароль врача через защищённый ввод, затем выполнит:
`/auth/login`, `/auth/me`, `/patients`, `/ai-requests`,
`/ai-requests/{request_id}/agent-context` и `POST http://127.0.0.1:8765/v1/simulate`.

Успешный результат: `ГОТОВО: транспорт работает. LLM НЕ вызывалась`.
Если сообщение говорит, что снимок подготовлен ранее, это ожидаемо.
Запросы, созданные до UI-6A, автоматически не подойдут для этого сценария.

## Проверки

```powershell
python -m ruff check backend scripts/mock_ai_server.py scripts/smoke_ai_connection.py
python -m ruff format --check backend scripts/mock_ai_server.py scripts/smoke_ai_connection.py
python -m pytest backend/tests/test_ai_mock_connection.py -v
```

Проверка работает без `aidoctor_test`, но полный регрессионный pytest запускать только
с `TEST_DATABASE_URL` выделенной тестовой базы.

## Безопасность и пределы

- Никогда не использовать этот механизм с реальным пациентом.
- Не проксировать порт 8765 в интернет.
- Не помещать имитатор внутрь кабинета врача на production.
- Техническая проверка доставки не доказывает качество медицинского AI и не означает готовность
  к переносу медицинских данных на внешнюю площадку.
- Для настоящего агента нужна отдельная авторизация, согласие/правовое основание обработки данных,
  проверка источников и безопасный валидируемый JSON-контракт, аудит и врачебное согласование.
- При каждом входе создаётся временная серверная сессия, которая истечёт сама;
  `logout` не выполняется, поскольку в текущем MVP он завершает все сеансы врача.
