# AIDoctor — аудит ручного отката перед фронтендом

Инструмент **не удаляет и не изменяет проектные файлы**, не соединяется с БД,
не читает `.env` и не запускает миграции. Эталон составлен по последнему архиву
`AIDoctor-master (4).zip` до локального ручного отката, исключая Demo Bridge и Live Demo,
и по файлам `6.6 FINAL`, совпадающим с этим архивом.

## Установка

Распакуйте папку `audit/` в корень AIDoctor.

```powershell
python audit/check_rollback.py . --report audit/rollback_report.json
```

Отчёт содержит только имена путей и результаты сравнения хешей,
без конфиденциальных переменных окружения.

Если файлы намеренно редактировались после этапа 6.6, отличия SHA-256
могут быть нормальными. Не восстанавливайте файлы автоматически.

## Проверки после анализа отчёта

```powershell
git status --short
python -m ruff check backend
python -m alembic -c alembic.ini current -v
python -m alembic -c alembic.ini heads
python -m alembic -c alembic.ini check
python -m pytest backend/tests/test_stage6_final_unit.py -v -rs
```

Полную регрессию `python -m pytest backend/tests -v -rs` проводите только
при корректно выделенной безопасной тестовой БД PostgreSQL. Тестовые фикстуры
могут пересоздавать таблицы, рабочую БД использовать нельзя.

## Важные ограничения

- Эталон сравнивает состав и байты 224 файлов этапа 6.6, но не подтверждает
  состояние PostgreSQL, Docker, внешнего хостинга или Git-коммитов.
- `README.md` и `.env.example` проверяются на наличие и устаревшие демо-ссылки,
  а не на полное совпадение.
- Даже если всё совпало, тесты доступа и PostgreSQL нужны отдельно.
- Никогда не удаляйте `aidoctor_demo` или рабочие базы через скрипт.
- Закрытый PHP-конфиг и данные на Hoster.ru проверяются вручную, отдельно.
