# AIDoctor — отчёт этапов 1–2 (17.10.2026)

Источник: загруженный архив `AIDoctor-master.zip`, с применением ранее проверенных правок шкал. Репозиторий GitHub после загрузки архива мог измениться; перед слиянием сравнить diff.

## Реализовано
- Авторизация логин/пароль с PBKDF2-SHA256 и восьмичасовыми bearer-сессиями (в БД хеш токена).
- CLI для локального создания admin/doctor/patient; публичного signup нет.
- Проверки доступности пациента по роли, связь врач–пациент; создание врача автоматически привязывает нового пациента.
- Контролируемая выдача списка пациентов, чтение истории и визитов.
- Схемы SQLAlchemy для универсальных наблюдений и метаданных вложений.
- Alembic миграции (пользователи и вложения/наблюдения), поддержка PostgreSQL через DATABASE_URL_OVERRIDE.
- Совместимость путей /api/v1 сохранена, но теперь требуется токен.

## Проверено фактически
- `pytest backend/tests -q`: **19 passed, 2 warnings** (Python 3.13, Linux).
- `alembic upgrade head` на чистой SQLite — успешно.
- `alembic upgrade bb442bccae1b`, вставка `legacy-p`, затем `upgrade head`: запись сохранена.
- `python -m compileall` на backend — успешно.

## Не сделано и не проверено
- Подключение к живому PostgreSQL, миграция данных между СУБД, резервное копирование.
- Защита интернет-сервера (TLS, rate limits, password lockout, аудит, CSRF/CORS и инфраструктурная настройка).
- Загрузка/выдача PDF, DOC, аудио; имеются только таблицы метаданных.
- UI Windows/Android, LLM, клиническая оценка, алерты.
- Фактическая сборка на Windows и Android.

## Критические ограничения
- Не размещать этот backend в публичном интернете без security hardening.
- Не использовать реальные идентифицируемые медицинские данные.
- Старые клиенты без токена получают 401: это изменение безопасности.
- Переход на PostgreSQL без механизма миграции содержимого не переносит данные.
